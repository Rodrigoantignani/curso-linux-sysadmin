Aula 19.6 · Samba: a ponte com o cliente Windows

O coração desta aula: separar autenticação Samba, autorização do share e permissão Unix ao testar um arquivo compartilhado.

1 · Aquecimento

  1. Uma senha Samba aceita demonstra permissão de escrita no diretório Unix?
  2. O nome mostrado no caminho UNC precisa ser igual ao caminho no disco?
  3. Quando dois programas usam o mesmo arquivo, as regras de acesso deixam de valer?

2 · Por que importa

O cliente pede uma pasta pelo nome do compartilhamento. O servidor autentica uma identidade e tenta acessar um caminho local. Cada etapa pode negar um pedido por uma razão diferente.

Quando a senha funciona, mas a gravação falha, conceder acesso anônimo troca o problema por exposição. Você precisa descobrir qual identidade chegou ao arquivo e qual regra a restringiu.

Ponte Windows

A unidade de rede é uma apresentação do cliente. O share é uma definição do servidor; o caminho real e suas permissões continuam existindo no Linux, mesmo quando o Windows mostra uma letra de unidade.

3 · Modelo mental

A conta Unix identifica o dono ou membro do grupo local. O cadastro Samba fornece a credencial usada na autenticação SMB. A conta desta aula não precisa de senha Unix nem login interativo.

O share permite apenas o grupo dedicado. Depois dessa autorização, o sistema de arquivos ainda aplica dono, grupo e modo; uma política ativa também pode restringir a operação.

O bit setgid no diretório faz os novos objetos herdarem seu grupo. Ele não concede leitura ou escrita sozinho; os demais bits e a configuração do share precisam ser coerentes.

Rocky × Debian

No Debian a unidade é smbd; no Rocky, smb. A configuração fica em /etc/samba/smb.conf nas duas famílias, mas a política SELinux exige cuidado adicional no Rocky.

A instalação principal configura escuta direta TCP 445, nomes pelo DNS do lab e nenhum compartilhamento anônimo. Não habilite SMB1 nem descoberta NetBIOS para resolver um erro de nome.

Decida 1

O login é aceito e criar arquivo retorna acesso negado. Qual investigação ajuda primeiro?

A. Conceder acesso total a todos. B. Trocar o nome da VM e remover a senha. C. Conferir identidade, share e permissões do caminho real.

5 · Lab guiado

Passo 1 · Instalar com os serviços bloqueados

Palpite: O pacote pode abrir a escuta antes da configuração restrita?

Na VM 204, como root, confira a interface e uma instalação nova. Se um dos pacotes ou arquivos já pertencer a outro uso, pare e revise o inventário.

set -eu
test ! -L /etc/m19-lab.env
test "$(stat -c '%U:%G:%a' /etc/m19-lab.env)" = root:root:644
cat /etc/m19-lab.env
. /etc/m19-lab.env
test "$LAB_IP" = 192.0.2.204
ip -4 -o address show dev "$LAB_IF" | grep -F '192.0.2.204/24'
if dpkg-query -W -f='${Status}' samba 2>/dev/null | grep -q 'install ok installed'; then
  printf '%s\n' 'STOP: Samba already installed' >&2; exit 1
fi
test ! -e /etc/samba/smb.conf
test ! -e /root/m19a6
for unit in smbd nmbd samba-ad-dc; do
  test "$(systemctl is-enabled "$unit" 2>/dev/null || true)" != masked
done
install -d -m 700 /root/m19a6
systemctl mask smbd.service nmbd.service samba-ad-dc.service
apt-get update
apt-get install -y samba smbclient
cp -a /etc/samba/smb.conf /root/m19a6/smb.conf.package

Saída esperada: Os serviços de compartilhamento continuam mascarados enquanto você prepara contas, caminho e restrição de escuta.

Verifique: Não confunda o cliente smbclient com o servidor. Uma ferramenta instalada não prova que uma porta já deveria estar aberta.

Passo 2 · Construir grupo e caminho

Palpite: O grupo dos arquivos novos vem só do nome digitado no cliente?

if getent passwd aluno19 >/dev/null; then
  printf '%s\n' 'STOP: aluno19 exists' >&2; exit 1
fi
if getent group m19share >/dev/null; then
  printf '%s\n' 'STOP: m19share exists' >&2; exit 1
fi
test ! -e /srv/samba/m19-curso
groupadd m19share
useradd --no-create-home --shell /usr/sbin/nologin --gid m19share aluno19
install -d -o root -g m19share -m 2770 /srv/samba/m19-curso
printf '%s\n' 'M19 Samba: OK' > /srv/samba/m19-curso/leia.txt
chown root:m19share /srv/samba/m19-curso/leia.txt
chmod 660 /srv/samba/m19-curso/leia.txt
id aluno19
namei -l /srv/samba/m19-curso/leia.txt
runuser -u aluno19 -- cat /srv/samba/m19-curso/leia.txt

Saída esperada: A conta Unix pertence ao grupo dedicado e consegue ler o arquivo. O diretório tem grupo m19share e modo 2770.

Verifique: Confira a travessia dos diretórios ancestrais. Não altere uma árvore preexistente inteira para acomodar um único compartilhamento.

Passo 3 · Cadastrar a credencial Samba

Palpite: Criar a conta Unix cadastrou automaticamente uma senha SMB?

smbpasswd -a aluno19
smbpasswd -e aluno19
pdbedit -L -u aluno19
getent passwd aluno19

Saída esperada: A senha é solicitada interativamente e o cadastro Samba mostra somente a conta prevista. O shell Unix continua sem login interativo.

Verifique: Não escreva a senha em argumento de comando, captura de tela ou material compartilhado. A mesma pessoa pode ter credenciais diferentes nos dois contextos.

Passo 4 · Definir o share e limitar a escuta

Palpite: O nome do share revela obrigatoriamente o caminho no disco?

cat > /etc/samba/smb.conf <<EOF
[global]
    workgroup = WORKGROUP
    server role = standalone server
    security = user
    map to guest = Never
    interfaces = 127.0.0.1 $LAB_IP/24
    bind interfaces only = yes
    smb ports = 445
    server min protocol = SMB2_02
    hosts allow = 127.0.0.1 192.0.2.0/24
    hosts deny = ALL
    log file = /var/log/samba/log.%m
    max log size = 1000

[curso]
    path = /srv/samba/m19-curso
    browseable = yes
    read only = no
    guest ok = no
    valid users = @m19share
    create mask = 0660
    directory mask = 2770
    force directory mode = 2000
EOF
testparm -s /etc/samba/smb.conf
systemctl unmask smbd.service
systemctl enable --now smbd.service
ss -ltnp '( sport = :445 or sport = :139 )'

Saída esperada: A escuta inclui loopback e endereço isolado na 445. Não há escuta 139 nem bind no endereço de gestão.

Verifique: Com firewall preexistente, autorize TCP 445 somente da rede isolada ao endereço isolado, pelo plano da 19.1. Mantenha nmbd e samba-ad-dc mascarados neste servidor standalone.

Os pacotes trouxeram unidades que este desenho não usa. Registre essas máscaras deliberadas; não as remova na limpeza enquanto o lab standalone estiver instalado.

Passo 5 · Provar leitura e escrita pelo cliente

Palpite: Listar shares comprova que um arquivo pode ser gravado?

Na VM 202, como student, consulte explicitamente o DNS do lab. A resolução de gestão foi preservada; a opção -I fixa o destino SMB sem trocar o DNS global. A senha será pedida a cada chamada.

sudo apt-get install -y smbclient
dig @192.0.2.204 smb.lab.test A +short
install -d -m 700 ~/m19-smb-client
cd ~/m19-smb-client
printf '%s\n' 'M19 client: OK' > prova.txt
smbclient -I 192.0.2.204 -L //smb.lab.test -U aluno19
smbclient -I 192.0.2.204 //smb.lab.test/curso -U aluno19   -c 'ls; get leia.txt; put prova.txt; get prova.txt retorno.txt'
cmp prova.txt retorno.txt

Saída esperada: O marcador é lido, o cliente grava seu arquivo e a cópia de retorno é idêntica. A listagem isolada não substitui essas operações.

Verifique: Na VM 204, confira stat -c '%U:%G %a %n' /srv/samba/m19-curso/prova.txt. O grupo deve continuar dedicado, sem escrita para qualquer usuário.

Passo 6 · Conferir a ponte Windows e a política

Palpite: Um cliente que já tem outra sessão pode reutilizar uma identidade inesperada?

No Windows 11 já autorizado, consulte o DNS do lab explicitamente e confirme a rota isolada. O mapeamento por IP abaixo evita mudar o DNS global; a consulta anterior continua provando o registro do nome.

Resolve-DnsName smb.lab.test -Server 192.0.2.204
Test-NetConnection 192.0.2.204 -Port 445
net use
net use Z: \\192.0.2.204\curso /user:aluno19 *
Get-SmbConnection | Select-Object ServerName,ShareName,UserName,Dialect
Get-Content Z:\leia.txt
Set-Content -Path Z:\windows19.txt -Value 'M19 Windows: OK'
Get-Content Z:\windows19.txt

Saída esperada: A conta autenticada lê e grava no share. Se Z: já estiver em uso, escolha uma letra livre e ajuste somente os comandos da própria sessão de lab.

Verifique: Registre o dialeto negociado e a identidade. Não conclua que uma conta foi usada só porque o nome apareceu no prompt de senha.

No Rocky comparativo, somente se você preparar um servidor dedicado equivalente, instale samba, samba-client e policycoreutils-python-utils, mascare smb antes da instalação e configure endereço e regra restritos antes de iniciá-lo.

getenforce
ls -Zd /srv/samba/m19-curso
semanage fcontext -l | grep -F '/srv/samba/m19-curso' || true
semanage fcontext -a -t samba_share_t '/srv/samba/m19-curso(/.*)?'
restorecon -Rv /srv/samba/m19-curso
ausearch -m AVC -ts recent

Execute o bloco de rótulo apenas na árvore dedicada criada para a comparação e sem regra local anterior. Se a regra existir, confira-a. Não use liberação global de todos os arquivos para Samba.

6 · Quebre e conserte

Interrompa o defeito anterior antes de criar o seguinte. Os dois primeiros testes usam a VM 204 como root e o cliente Linux já autenticado.

Quebra 1 · Diretório sem travessia para o grupo

Sintoma: Aplique chmod 2700 /srv/samba/m19-curso; o login permanece possível, mas a operação no share falha.

Investigação: Confira id aluno19, o caminho com namei e o registro da tentativa.

Causa: A conta foi autenticada, mas o grupo não atravessa o diretório.

Conserto: Restaure chmod 2770 /srv/samba/m19-curso.

Verifique: Repita leitura e gravação; confirme grupo e modo do arquivo novo.

Prevenção: Teste acesso com a identidade do serviço, não apenas como root.

Quebra 2 · Share apontando para lugar inexistente

Sintoma: Faça uma cópia de smb.conf e troque somente o caminho do share por /srv/samba/m19-ausente, que deve não existir.

Investigação: Rode testparm, recarregue e compare o nome do share com o caminho real.

Causa: Sintaxe válida não demonstra existência nem permissão do diretório configurado.

Conserto: Restaure a cópia da configuração desta aula, valide e recarregue smbd.

Verifique: Uma nova conexão do cliente volta a alcançar o marcador.

Prevenção: Confirme o destino após qualquer alteração de caminho ou ponto de montagem.

test ! -e /srv/samba/m19-ausente
cp -a /etc/samba/smb.conf /root/m19a6/smb.conf.before-fault
sed -i 's|path = /srv/samba/m19-curso|path = /srv/samba/m19-ausente|' /etc/samba/smb.conf
testparm -s /etc/samba/smb.conf
systemctl reload smbd
# After observing the failed NEW client connection:
cp -a /root/m19a6/smb.conf.before-fault /etc/samba/smb.conf
testparm -s /etc/samba/smb.conf
systemctl reload smbd

Quebra 3 · Sessão Windows com outra identidade

Sintoma: Se o cliente já tem sessão com outro usuário, o novo mapeamento pode recusar a identidade diferente. Não crie outra conta para fabricar esse caso.

Investigação: Leia net use e Get-SmbConnection no cliente autorizado.

Causa: A sessão existente pertence ao contexto do cliente; alterar a senha do servidor não limpa esse contexto.

Conserto: Feche arquivos do próprio share, confira net use Z: e remova apenas o mapeamento de lab com net use Z: /delete, se ele realmente apontar para este share.

Verifique: Refaça a conexão interativa e confirme a identidade negociada. Se outra sessão em uso persistir, coordene sua conclusão sem apagá-la à força.

Prevenção: Registre mapeamentos por contexto e nunca desconecte todos os compartilhamentos do usuário.

7 · Armadilhas

O share pode ser gravável e o diretório continuar sem escrita; o inverso também acontece. A autorização efetiva precisa passar por todas as camadas que participam da operação.

A máscara de criação restringe modos solicitados; ela não recupera acesso negado pelo diretório nem substitui a decisão do share. Confira o resultado real com um arquivo novo.

O endereço de gestão não deve responder a SMB. Confirme essa negativa de um cliente autorizado a observar a gestão, sem fazer varredura de outras máquinas.

Decida 2

Um diretório no Rocky tem modo e grupo corretos, mas o registro mostra negativa SELinux no caminho dedicado. Qual opção corresponde ao lab?

A. Permitir que Samba exporte qualquer arquivo do sistema. B. Conferir a regra específica samba_share_t e reaplicar o contexto persistente. C. Desativar SELinux permanentemente.

Flashcards: responda em voz alta, sem procurar a linha de comando. Uma resposta boa nomeia a evidência que pode contrariar sua hipótese.

Último exercício: feche o terminal que fez a configuração. Em uma sessão nova, reconstrua o caminho do pedido usando seus registros, sem depender de variáveis da sessão anterior.

A limpeza desta aula remove arquivos temporários de teste e restaura os defeitos. Preserve serviços, dados e configuração dedicados ao M19 para o desafio integrado da 19.9.

Crie m19a6-fim apenas depois do teste externo. Anote o ponto de restauração anterior e não restaure uma VM sem avaliar os serviços que outras aulas já usam.

11 · Na vida real

Missão de observação: escolha um serviço já autorizado e acompanhe um único pedido nos registros disponíveis, sem alterar configuração, permissões, usuários ou firewall.

Entregue um desenho com cliente, nome, endereço, processo e arquivo. Marque o que foi medido e o que ainda é hipótese; não transforme ausência de evidência em autorização para mudar.

  6. Teste uma operação permitida e outra que deve continuar negada; root não representa o acesso do aluno.

  1. A credencial SMB é cadastrada separadamente; a conta Unix fornece identidade local.
  2. A definição [curso] associa o nome do share ao seu parâmetro de caminho.
  3. Root tem privilégios diferentes; o pedido Samba usa a identidade Unix autenticada e as políticas aplicáveis.
  4. Os novos objetos herdam o grupo do diretório; o modo continua sendo outra verificação.
  5. Confirme leitura e gravação autorizadas e confira que acesso anônimo ou fora do escopo continua negado.
